# DEV_GUIDE — запуск, логи, режимы (BeeAgent)

## 1) Требования
- Python 3.12+
- uv (менеджер окружений/зависимостей)
- Telegram Bot Token (для запуска UI в Telegram)
- (опционально) OpenAI API key — если включим LLM-объяснения

## 2) Установка (dev)
1) Установить uv (один раз в системе)
2) В корне проекта:
   - `uv sync`

Запуск выполняй через `uv run`, активация venv не нужна.

### 2.1) Управление зависимостями (uv)

Источник правды по зависимостям:
- `pyproject.toml` — список зависимостей и ограничения версий (constraints)
- `uv.lock` — зафиксированные версии для воспроизводимой установки

Правило: после `uv add/uv remove/uv lock --upgrade` всегда коммить `pyproject.toml` и `uv.lock`.

| Что сделать | Команда | Что произойдёт / что проверить |
|---|---|---|
| Поставить зависимости по lock | `uv sync` | Ставит ровно то, что в `uv.lock`. |
| Запустить команду в окружении | `uv run python3 config/start.py` | Запуск без активации venv. |
| Добавить runtime-зависимость | `uv add <pkg>` | Обновит `pyproject.toml` и `uv.lock`. |
| Добавить dev-зависимость | `uv add --dev <pkg>` | Уйдёт в dev-группу (если используешь). |
| Удалить зависимость | `uv remove <pkg>` | Обновит `pyproject.toml` и `uv.lock`. |
| Посмотреть дерево зависимостей | `uv tree` | Диагностика зависимостей. |
| Апгрейднуть зависимости | `uv lock --upgrade` | Обновит `uv.lock` в рамках constraints. |

### Таблица команд `uv` для зависимостей

| Что сделать                                                 | Команда                                         | Что произойдёт / что проверить                                                 |
| ----------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------ |
| Поставить зависимости по lock (как на CI/у других)          | `uv sync`                                       | Ставит ровно то, что в `uv.lock`. Должно быть воспроизводимо.                  |
| Запустить команду в окружении проекта                       | `uv run python3 config/start.py`                | Не нужно активировать venv. Используется окружение, которое ведёт `uv`.        |
| Добавить зависимость (runtime)                              | `uv add python-telegram-bot`                    | Обновит `pyproject.toml` и `uv.lock`. Коммить оба файла.                       |
| Добавить зависимость с версионным ограничением              | `uv add "python-telegram-bot>=22.6,<23"`        | Зафиксирует constraint в `pyproject.toml`, а конкретику — в `uv.lock`.         |
| Добавить dev-зависимость (тесты/линтеры)                    | `uv add --dev pytest`                           | Уйдёт в dev-группу (зависит от структуры `pyproject.toml`). Коммить `uv.lock`. |
| Удалить зависимость                                         | `uv remove python-telegram-bot`                 | Удалит из `pyproject.toml` и обновит `uv.lock`.                                |
| Показать дерево зависимостей                                | `uv tree`                                       | Удобно для проверки “почему поставилось”.                                      |
| Обновить lock (без изменения constraints)                   | `uv lock`                                       | Пересоберёт `uv.lock` под текущие ограничения.                                 |
| Обновить lock с апгрейдом пакетов (в рамках constraints)    | `uv lock --upgrade`                             | Поднимет версии до максимально возможных внутри ограничений.                   |
| Обновить конкретный пакет                                   | `uv lock --upgrade-package python-telegram-bot` | Апгрейд только выбранного пакета (если команда доступна в твоей версии uv).    |
| Установить только dev-зависимости (если используешь группы) | `uv sync --group dev`                           | Ставит группу dev (если у тебя она есть).                                      |
| Установить без dev-зависимостей (прод-подобно)              | `uv sync --no-dev`                              | Ставит только runtime deps.                                                    |
| Обновить `uv` (в системе)                                   | `uv self update`                                | Если uv установлен как отдельная утилита (не через OS repo).                   |

> **Правило проекта (must):** после любых изменений зависимостей коммить **и** `pyproject.toml`, **и** `uv.lock`, иначе у других не совпадёт окружение.

## 3) Настройка
- Скопировать `.env.example` → `.env`
- Заполнить ключи:
  - `TELEGRAM_BOT_TOKEN=...`
  - (опционально) `OPENAI_API_KEY=...`
- Проверить `config/settings.yml` (пороги, allowlist, режимы)

## 4) Запуск
- `bash start.sh`

`start.sh` делает:
- `uv sync`
- `uv run python3 config/start.py`

## 5) Режимы
В BeeAgent режимы такие:

- **manual-run** (через Telegram): запуск по команде `/run_oos` или кнопке
- **scheduled-run** (позже): запуск по расписанию (но с approval gate)
- **dry-run** (по умолчанию для pre-MVP): ничего не меняет в системах клиента, только:
  - считает алерты
  - формирует задачи как `draft`
  - генерирует отчёт

> Важно: любые “действия” (создание задач как “готовых”) — только после approve.

## 6) Логи
- stdout
- `logs/app.log`

Формат: время + уровень + сообщение.
Секреты в логах запрещены.

## 7) Артефакты в storage/
Минимальный набор для pre-MVP:

- `storage/mock/<dataset_id>/...` — мок-датасеты (генерация/фикстуры)
- `storage/runs/<run_id>/run.json` — мета-инфо о запуске
- `storage/runs/<run_id>/alerts.json` — найденные отклонения / OOS
- `storage/runs/<run_id>/tasks.json` — задачи (draft/approved/rejected)
- `storage/artifacts/<run_id>/report.md` — текстовый отчёт (Telegram-friendly)
- `storage/artifacts/<run_id>/report.html` — “красивый” отчёт (для демонстрации)
- (опционально) `storage/artifacts/<run_id>/report.xlsx` — Excel отчёт

## 8) Правило безопасности (must-have)
Даже если агент “уверен”, система может/должна отказаться от действий:
- нет approval
- пользователь не в allowlist
- данные пустые/сомнительные (например, нет stock или нет shelf_signal)
- превышены лимиты/ограничения, заданные в правилах (позже)
