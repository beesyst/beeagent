# BS-13 governed DAST qualification and operation

## Enforcement gate

The original ManagedEgress is a destination firewall, not an HTTP counter. Retained `dast_preflight` tests reproduce two HTTPS requests at cap=1 for reused, separate and concurrent connections. Existing trusted single-request capture behavior remains unchanged.

The active path now uses `dast_runner.py`, `dast_mediation.py`, `dast_socket_worker.py` and `dast_worker.py`. ZAP has a separate networkless Bubblewrap namespace and only a private UNIX gate socket. BeeAgent terminates CONNECT/TLS, parses HTTP/1.1 with pinned h11, atomically reserves the shared run budget before connecting/sending, constructs the upstream GET and independently validates authority, origin, DNS, exact IP/port and TLS hostname/certificate. No transparent tunnel exists. Bodies, ambiguous framing, cookies/authentication, non-GET methods, upgrades, foreign destinations and redirects are rejected. The connector opens only the approved endpoint inside the existing validated ManagedEgress namespace and passes a connected descriptor to the host; the scanner cannot reach the connector. Actual independent HTTPS tests accept exactly one request at cap=1 for keep-alive, separate and concurrent attempts.

## Provider and limits

Provision the exact [ZAP 2.17.0 Core ZIP](https://github.com/zaproxy/zaproxy/releases/tag/v2.17.0), Apache-2.0, 108340737 bytes, SHA-256 `0cb73b7f72d12c263fb61de304edb82a455d7aa4e1813c216c061765c306f5b7`, as an operator-owned regular file without group/other write permissions. Runtime verifies the complete ZIP and every selected add-on before snapshotting; it never downloads or updates. The authoritative selected add-on digests are `dast_runner.ADDONS`: bundled active rules 78, commonlib 1.39.0, network 0.25.0, database 0.9.0, oast 0.24.0, callhome 0.20.0 and pscan 0.6.0. All other add-ons are removed. Mandatory callback-capable libraries have no independent network route.

The fixed worker disables passive scanners and all active rules, enables only Path Traversal rule 6 at LOW/MEDIUM strength/threshold and verifies selection. It waits for ZAP's asynchronous site cache after importing the one approved URL. No AI commands, arbitrary flags, scripts, spider, uncontrolled rule selection, callbacks or destination expansion are exposed.

Qualification uses Linux rootless Bubblewrap, nftables, pinned pasta and OpenJDK 25 at `/usr/lib/jvm/java-25-openjdk-amd64/bin/java` with read-only `/usr`, `/lib`, `/lib64` and `/etc/java-25-openjdk`. Missing prerequisites fail closed. Limits are 256 MiB Java heap, bounded native regions, 4 GiB per-process address space, CPU/deadline enforcement, 256 descriptors, 16 MiB per file, 128 MiB `/tmp`, no core dump and 16 KiB projected output. Existing capture limits remain 64 descriptors/64 KiB. Upstream bodies are transient and capped at 256 KiB; the private ZAP API is capped at 2 MiB to accommodate JSON escaping of binary content. These per-process limits do not establish an aggregate cgroup memory guarantee.

## Approval and CLI

`config/settings.yml` remains authoritative. The additive `beescan.dast` mapping contains exactly `enabled` and `approval`, shipped disabled/null. Older configurations without the mapping remain compatible. Enabled execution requires the enabled module, current trusted local CLI operator context and a separate explicit active approval. `trusted_local_enabled`, `adaptive.enabled`, discovery approval, task text and scanner output never grant active authority.

Approval contains exactly `transport`, `approved`, `method`, `entries`, `request_budget`, `seconds` and `archive`. Transport uses the existing complete ProbePolicy schema with operator/scope/Mission/Target identities, canonical HTTPS origin, fixed IP/port, current validity and the managed namespace pair; its existing single-request contract is unchanged. The independent approval requires `approved: true`, `method: active_dast`, one bounded printable ASCII relative entry without fragment/backslash, cap 1–100, deadline 10–60 seconds and an absolute path to the pinned ZIP. Keep credentials and sensitive query values out of settings.

After supplying approval, use `./start.sh beescan investigate --target https://authorized.example --task 'Assess Path Traversal'`. Task text selects this capability; entry, rule and authority remain host-owned. This MVP checks one explicitly approved parameterized entry; automatic parameter discovery and comprehensive coverage are not claimed. Task-file DAST routing requires explicit enablement.

`investigate --inspect CASE` validates checkpoint/evidence/report bytes. `investigate --resume CASE --task 'Assess Path Traversal'` requires fresh current authority and the same derived approval identity, including scope, destination, entry and budgets. Ready evidence is reused without requests. Clean incomplete segments can be retried within eight segments; pending, tampered, foreign and unverified-cleanup records fail closed. Existing ArtifactAPI, fsync/read-back, atomic Case publication and a no-follow directory lock are reused. Case schemas 1/2 remain compatible; DAST uses schema 3.

## Handoff and artifacts

BeeScan It14 owns the public offline contract in `beescan.capabilities.dast` and `beescan/docs/DAST.md`. The host binds scanner request/response digests to actual mediated exchanges and protected artifact bytes before constructing typed execution/outcome records. Persistent data allowlists identities, digests, status codes, counts, bounded lifecycle/error codes and fixed report text. ZAP databases, bodies, headers, cookies and arbitrary descriptions remain disposable sandbox data.

Completed stages write `egress_lifecycle.json`, `dast_execution_status.json`, `dast_evidence.json`, `dast_handoff.json`, `report.json`, `report.md` and `investigation_status.json`. Abrupt setup/persistence failures remain pending. No artifact grants authority. Positive matched parameter evidence yields CANDIDATE, never VERIFIED. ZAP progress=100 is insufficient proof of negative coverage: a fixed target returns PARTIAL without a false Finding; NO_MATCH requires independent completed-check coverage.

## SCA and security review

The 2.17.0 core ZIP and every selected add-on were inspected after integrity verification. The earlier 71-component metadata inventory contains both actual loaded/shipped JARs and metadata-only matches. Core ships Commons Configuration 1.10, Commons Lang 2.6 and Log4j 2.25.2. The selected Database add-on ships Jackson 2.19.1. The selected Network add-on ships Netty 4.1.100.Final, HttpClient 5.2.1, HttpCore 5.2 and HttpCore H2 5.2. The selected Common Library also embeds Jackson metadata/classes. The worker does not reference these libraries directly; they remain reachable through the untrusted ZAP process and its enabled add-ons. h11 0.16.0 had no OSV match in the recorded query. Metadata-only classification does not prove that a component is absent from shaded code or the JRE.

The risk-based disposition is **GO for this exact pinned rule-6 profile**, not a claim that the provider has no CVEs. Commons Lang 2.6 is affected by [GHSA-j288-q9x7-2f5v](https://github.com/advisories/GHSA-j288-q9x7-2f5v), but the Path Traversal rule bytecode does not call `ClassUtils`; it uses ZAP's HTTP message/URI APIs and its payload matcher. Database's Jackson 2.19.1 is below patched releases for [GHSA-3pjw-73gf-8qr5](https://github.com/advisories/GHSA-3pjw-73gf-8qr5) and related deserialization/SSRF advisories, but rule 6 does not deserialize target JSON into application Records or `InetSocketAddress` objects. Network's Netty and HttpComponents versions are affected by HTTP parsing, request-smuggling and resource-exhaustion advisories, including [GHSA-38f8-5428-x5cv](https://github.com/advisories/GHSA-38f8-5428-x5cv), [GHSA-fghv-69vj-qj49](https://github.com/advisories/GHSA-fghv-69vj-qj49), [GHSA-hf6x-8p5f-cgmf](https://github.com/advisories/GHSA-hf6x-8p5f-cgmf) and [GHSA-hjcp-jmpx-g3qm](https://github.com/advisories/GHSA-hjcp-jmpx-g3qm), but target HTTP cannot reach their parsers directly.

The host gate is the only target-facing endpoint: it terminates TLS, parses target responses with h11, rejects malformed/redirect responses and headers above 8 KiB, caps transient bodies at 256 KiB, then re-emits only a new `Content-Length` response with an optional bounded content type to ZAP's loopback proxy. It rejects Transfer-Encoding, bodies, duplicate headers, foreign authority and all non-GET scanner traffic before upstream connection. Netty receives only ZAP-generated loopback proxy traffic; HttpComponents receives normalized bounded data without `Content-Encoding`; neither has a target-controlled front-end/proxy differential required by the smuggling advisories. The worker has no direct target route, credentials, writable host mounts or persistent raw artifact access. Bubblewrap, `--clearenv`, read-only runtime mounts, 256 MiB Java heap, 64 MiB direct memory, 4 GiB address space, deadline, output/file-descriptor limits and verified process cleanup contain availability failures as incomplete outcomes rather than trusted completion.

The official 2.17 manifest offers newer compatible add-ons (ascanrules 84, commonlib 1.44.0, network 0.32.0 and oast 0.26.0), but rule 6 declares Network and OAST dependencies and OAST declares Database. Replacing only selected add-ons would require a new provider qualification and does not remove core Commons Lang 2.6. The current integrity-pinned 2.17.0 set is therefore retained. Residual risk is limited to a scanner sandbox denial of service or an unknown ZAP-internal path that bypasses the documented rule-6 dataflow; it cannot expand target authority, create a verified finding, preserve raw target data or continue after cleanup verification fails.

The evidence set is `/tmp/bs13-provider-sca.json`, `/tmp/bs13-sca-advisories.json`, `/tmp/bs13-zap-archive-members.txt` and `/tmp/bs13-zapversions-2.17.xml`. Any future provider, rule, input channel, proxy mode, response pass-through, mount or resource-limit change invalidates this disposition and requires fresh inventory, SCA and acceptance. The feature remains disabled by default until an explicit active approval is supplied.
